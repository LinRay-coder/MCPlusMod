## C. 兼容性与崩溃边界

### C1. 与主流 mod 共存（静态结论 + 人工验证建议）OK
> **注意**：Minecraft 26.1 较新，JEI / Cloth Config / GeckoLib 的 26.1 稳定版可能尚未全部发布。以下为**代码层**兼容性结论；实际共存需在对应版本可用后人工验证。

| Mod | 代码层冲突面 | 静态结论 | 人工验证点 |
|---|---|---|---|
| **JEI** | 物品/配方展示。本 mod 用标准注册 + datagen 配方，无自定义配方类型 | ✅ 无冲突面 | JEI 中能搜到全部物品并显示合成/切石/锻造配方 |
| **Cloth Config** | 配置界面库。本 mod 无配置项、不引用其 API | ✅ 完全无交集 | 有无 Cloth Config 均能正常启动 |
| **GeckoLib** | 动画渲染库。本 mod 无自定义实体/动画、无 mixin | ✅ 完全无交集 | 同装不报错，二者渲染互不影响 |
| **其它含 AttackEntityCallback 的战斗 mod** | 共用同一事件 | ✅ 低风险：本 mod 回调返回 PASS 不吞事件 | 与其它战斗 mod 同装，攻击行为叠加正常 |

### C2. 崩溃边界测试
- [ ] **无第三方 mod 环境**：仅装 Fabric Loader + Fabric API 启动 → 预期**正常加载**，手套/装备/方块全部可用（已移除 Trinkets 硬依赖，不再有缺依赖拒绝加载或 `NoClassDefFoundError` 风险）。
- [OK ] **纯服务端**：专用服务器加载 mod 不因客户端类（穿戴纹理/模型）报错（客户端资源不参与服务端逻辑）。
- [OK ] **数据包重载** `/reload`：不报标签/战利品表/配方错误。
- [OK ] **攻击非生物实体**（矿车/盔甲架/船）：手套逻辑判 `LivingEntity` 后跳过，不崩溃。
- [OK ] **手套放入护甲槽/其它槽**：仅主手提供属性与战斗效果，误放不触发、不崩溃。

### C3. 已知设计限制（非 bug）
- **手套只能附「击退 / 经验修补 / 耐久」**：这是刻意设计——手套加入 `mcplusmod:gloves` 标签由覆盖版 `knockback.json` 授予击退（原版击退 slots=mainhand，正好主手生效），并加 `enchantable/durability`（slots=any）；**不加** `enchantable/weapon`（否则解锁全部近战附魔）、**不加** `enchantable/armor`（保护/荆棘生效槽是 armor，主手拿着不触发，属无效附魔）。
- **手套护甲仅主手生效**：护甲/韧性修饰符绑定 `EquipmentSlotGroup.MAINHAND`，放进护甲槽不提供防护——这是「手持战斗手套」而非「穿戴护甲」的定位。
